# HoneyBot-IoT — Module 8 Model Evaluation (trained models + datasets)

This records the **actual trained models and their measured accuracy**, and where the
datasets live, so the results are reproducible and the numbers are honest.

## Datasets (`ml/datasets/`)

| File | Rows | What it is |
|---|---|---|
| `honeybot_training_dataset.csv` | 3 600 | Balanced labelled training set (600 per class × 6 classes), 29 features + `label`, generated by `ml/synth.py` with the **same schema** as live data. |
| `honeybot_live_dataset.csv` | 188 | **Real honeypot sessions** captured by running the attack simulator against the live stack, with rule-based weak labels (`ml/features.py`). |

Regenerate the live set any time with `GET /api/ml/dataset.csv` or `python -m ml.features out.csv`.

## Trained models (`ml/artifacts/`, produced by `python -m ml.train` + `python -m ml.forecast`)

| Model | File | Purpose |
|---|---|---|
| XGBoost classifier | `xgb_classifier.json` | 6-class attack classification |
| Isolation Forest | `isolation_forest.joblib` | anomaly / novelty score |
| LSTM forecaster | `lstm_forecast.keras` | per-device 24-h escalation risk |

The `ml_api` service also trains these automatically on first boot, so a fresh
`docker compose up` has a working model with no manual step.

## Honest reading of the numbers (important for the viva)

- **0.996 is on held-out *synthetic* data.** It proves the feature engineering and the
  train/serve pipeline are correct and that the six classes are learnable — it is **not**
  a claim of 99 % real-world accuracy.
- The **188 real lab sessions** all originate from a single source IP (the simulator runs
  on `localhost`), which makes the *rule* weak labels skewed (most sessions collapse to
  `protocol_exploit`/multi-protocol). So "agreement with the weak labels" on that set is
  low and is **not** a meaningful accuracy figure — the model's own per-session predictions
  are actually sensible (malware→malware, scan→scan). This is the known data limitation
  **LI-6**: real-world accuracy needs diverse, multi-source live traffic, i.e. an internet
  deployment (future work).
- Because the labels come from the rule engine, the model can partly *learn the rules*; the
  features it relies on include timing/ratio signals the rules do not use, which is what lets
  it generalise beyond them.

## Reproduce

```bash
# live dataset from the running stack
python -m ml.features ml/datasets/honeybot_live_dataset.csv
# train + evaluate (writes ml/artifacts/ and prints 5-fold CV)
python -m ml.train
python -m ml.forecast            # LSTM
```
